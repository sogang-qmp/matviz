# v0.26 — Structure builder (periodic table · Bravais templates · editable cell)

> **Roadmap provenance**: Tier 4 of the Crystal Viewer parity roadmap
> (v0.23–v0.26). See `Plan.md` §"Crystal Viewer parity roadmap".
> **Form-factor caveat**: unlike Tiers 1–3, this tier partially overlaps
> capabilities VSCode already provides. Re-interpreted below to fit the
> editor form factor rather than cloned from the standalone workbench.

## Goal

Add lightweight structure **authoring** to MatViz: create simple crystal
structures from a Bravais template, add atoms via a periodic table, and
edit coordinates / cell vectors in a table — with all edits **written
back to the underlying text buffer** so the file stays the source of
truth. This is the manual's `Build` + `Edit` menus, re-cast as a
VSCode-native round-trip rather than an in-memory-only builder.

## Design premise: text buffer is the model

The Crystal Viewer is a standalone app, so its builder holds structure
state in memory. MatViz is a `CustomTextEditorProvider` (migrated in
v0.19/v0.20) backed by a real `TextDocument`. Therefore every edit here
serializes to file text via a `WorkspaceEdit` and flows back through the
existing debounced reparse → 3D update loop. Benefits:

- No second source of truth; undo/redo piggybacks on VSCode's document
  undo (in addition to the v0.19 property-panel undo stack).
- The user's global preference — *save an `.xsf` for every relaxation* —
  is naturally served: authored structures are real files, exportable.
- Works with the existing exporters (`src/parsers/exporters.ts`).

## Technical notes / decisions

- **D1 — Which format to write.** Round-tripping edits back into the
  *original* format is ideal but not always loss-free (CIF symmetry,
  QE namelists). Policy: POSCAR and XSF round-trip fully; for
  read-mostly formats (CIF, QE out, PDB) an edit offers "export to
  POSCAR/XSF to enable editing" rather than mangling the source. Decide
  the exact allow-list at kickoff.
- **D2 — WorkspaceEdit granularity.** Prefer minimal-range edits
  (replace only the changed atom line / cell block) over full-document
  rewrites, to keep VSCode diff/undo clean. Full rewrite is the
  fallback when the format's layout can't be edited in place.
- **D3 — Reuse, don't rebuild.** Element data + colors/radii already
  exist (`elements-data.ts`); the periodic-table UI is presentation over
  that table. Bravais generation is pure geometry (basis × lattice) with
  no new rendering. This tier is mostly UI + serialization, little new
  3D code.
- **D4 — Overlap with VSCode text editing.** A power user can already
  edit POSCAR text directly and watch it reflow (v0.19). 26.1's table is
  a *structured convenience* over that, not a new capability — scope it
  as ergonomics, and don't over-invest versus the raw text path.

## Out of scope

- Symmetry-aware building (add one atom → symmetry-equivalents auto-
  populate). Interesting given spglib (v0.20) is present, but a distinct
  feature; note as a follow-up.
- Supercell *materialization* (writing an expanded supercell to file) —
  the viewer supercell is display-only today; making it writable is
  adjacent but separate.
- Interactive drag-to-move atoms in 3D (gizmo manipulation). Coordinate
  entry only in v0.26; drag editing is future work.
- Slab / interface / defect builders (vacancy, substitution wizards).

## Acceptance test fixtures

- Round-trip: load `silicon.poscar`, edit a coordinate, confirm file +
  view update and re-load matches.
- Build FCC Cu, SC Po, hexagonal graphite cell — each renders correctly
  and re-parses from its written file.
- Add an atom to `nacl`, confirm bonds/measurement include it.

## Decision gate (kickoff)

**Gate v0.26-A** — confirm the editable-format allow-list (D1) and the
WorkspaceEdit strategy (D2) before building the table, since they define
what "edit" safely means per format.

## Exit criterion

Editable table, Bravais templates, and periodic-table add each round-
trip through the text buffer without corrupting files; authored
structures render and re-parse; build + type-check clean;
SKILL.md/README updated if any CLI surface is added (likely none — this
tier is interactive-only).
