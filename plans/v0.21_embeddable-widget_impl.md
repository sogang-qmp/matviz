## 21.2 — Host shim layer (`src/webview/host.ts`)

Interface (single source `main.ts` imports):

```ts
export interface MatvizHost {
  postMessage(msg: unknown): void;      // outbound events (VSCode) / no-op or CustomEvent (embed)
  getState(): unknown;
  setState(s: unknown): void;
  // theme signal source
  onThemeChange(cb: () => void): void;
  currentTheme(): 'dark' | 'light';
}
```

- `host.vscode.ts`: wraps `acquireVsCodeApi()`; theme from
  `data-vscode-theme-kind` / `prefers-color-scheme` (moves the existing 1132-1136
  logic here verbatim).
- `host.embed.ts`: `postMessage` → optional `CustomEvent` dispatch on the widget
  root (lets the host page listen for `atomSelected` etc.); `getState/setState`
  → `localStorage['matviz:'+prefix]`; theme per 21.5.
- Build-time selection: esbuild `define` / alias so the webview entry pulls
  `host.vscode` and the embed entry pulls `host.embed`. `main.ts` becomes
  host-agnostic. This is the only edit to `main.ts` beyond removing the top-level
  `acquireVsCodeApi`.

## 21.3 — Mount API

```ts
MatViz.mount(prefix: string, opts?: {
  data?: string;              // structure text; if absent, read #<prefix>-data textContent
  format?: string;            // optional override; else auto-detect
  theme?: 'auto'|'light'|'dark';      // default 'auto'
  themeAttribute?: string;    // e.g. 'data-theme' on <html>  (21.5)
  themeClass?: string;        // e.g. 'dark'
  collapsed?: boolean;        // default true (21.4)
  supercell?: [number,number,number];
  style?: 'ball-stick'|'space-filling'|'stick'|'wireframe';
  iso?: number;               // isosurface level for volumetric
}): MatvizInstance
```

- Recipe idiom (matches `SVENG("id",[…])`): page has
  `<div id="{prefix}-viewer" …></div>` and
  `<script type="text/plain" id="{prefix}-data">…CIF/POSCAR/XSF…</script>`;
  one `MatViz.mount("{prefix}")` call.
- `mount()` injects the namespaced shell into `#{prefix}-viewer`, instantiates
  `CrystalRenderer`, wires the (collapsed) UI, parses `data`, renders.
- **All ids namespaced** by `prefix` (mirror the reference `$ = id => getElementById(prefix+'-'+s)`). No global ids → multiple widgets coexist.
- `MatvizInstance` exposes `{ setTheme, setStructure, dispose }` for host control.

## 21.4 — Collapsed-by-default chrome

- Reuse the v0.18 V2 floating chrome (toolbar, side panel, mode rail) but add a
  `data-collapsed` state on the widget root; CSS hides toolbar/panel/rail,
  leaves canvas + a single `⋯`/gear affordance (top-right, `opacity`-styled per
  house rule).
- Expand: click affordance → remove `data-collapsed`. Collapse: Esc, click-away,
  or re-click. Info pill + axis gizmo stay visible collapsed (they're the
  "figure caption", low-chrome).
- `collapsed: false` opt renders expanded (docs/authoring use).
- Responsive: verified at card widths 320–900 px (recipe cards are
  `max-width:680px`).

## 21.5 — Host-theme reactivity

Host signal is **known exactly** (`112-Gd2C-H/site/assets/site.js`):
`document.documentElement.dataset.theme` ∈ `{"light","dark"}`.

- `theme:'auto'` (default): resolve current theme in priority:
  (1) `themeAttribute` value on the target (default target
  `document.documentElement`, default attribute **`data-theme`**) →
  `"dark"`/`"light"`; else
  (2) `themeClass` present on the target; else
  (3) `prefers-color-scheme`.
- Reuse the `MutationObserver` pattern (main.ts:1135) retargeted to
  `document.documentElement` with `attributeFilter:['data-theme']` (overridable),
  plus the `matchMedia('(prefers-color-scheme: dark)')` listener. Both call
  `instance.applyTheme()` → `renderer.setColorPalette(theme)` +
  `renderer.updateTheme()` + canvas clear-color swap.
- **Blend option**: read host CSS vars via
  `getComputedStyle(document.documentElement).getPropertyValue('--bg'|'--fg'|'--border')`
  and use `--bg` as the canvas clear color and card border = `--border`, so the
  widget matches the site tokens (`#fff`→`#191b1f` etc.) rather than matviz's own
  hardcoded palette. Falls back to matviz palette if the vars are absent.
- `theme:'light'|'dark'` = fixed, no observers.
- Aux text (`info-pill`, hints) styled via `opacity` on `--fg`, not fixed hex
  (house rule).
- `MatViz.setTheme(prefix, 'light'|'dark'|'auto')` for explicit host control
  (parity with the shell's `◐` button if a host wants to drive it manually).

## 21.6 — Symmetry disabled in embed

- `withSymmetry` post-pass calls the spglib wrapper (`src/shared/spglibWasm.ts`).
  In the embed entry, alias that import to a no-op stub (esbuild alias) so the
  521 KB WASM never enters `matviz-embed.js` and no `wasm-unsafe-eval` is needed.
- CIF parser keeps its own `_space_group_name_*` → info pill shows it; other
  formats show `P1`. This is exactly the existing non-fatal fallback, so no
  renderer/UI change — only the build-time import alias.
- Gate-21.D: `grep -c wasm dist/matviz-embed.js` == 0.

## 21.7 — Recipe fragment + self-host asset

- New recipe `structure-viewer-matviz.html` for the `sogang-qmp/recipes` repo
  (staged in this repo under `web/` for review; final home is the recipes repo).
  House style: meta comment → 1-line intro + bullets → `Live demo` →
  `데이터 형식` → `복사해서 쓰기` (`<pre><code>` HTML-escaped). Korean 개조식,
  `<strong>` on keywords only.
- Asset paths mirror the live host: the **live demo** in the recipes repo uses
  `/static/lib/matviz-embed.js`; the **copy-source** block shows
  `../../assets/lib/matviz-embed.js` (a real depth-2 page like
  `electronic-structure/*/index.html`; note the depth `../` rule). Demo and
  copy-source cite the **same** mount code.
- Real integration example to mirror (`112-p31m-cell/index.html`): scoped
  `<style>` for the viewer card + `<div id="{prefix}-viewer">` +
  `<script type="text/plain" id="{prefix}-data">` inline structure +
  `<script src="../../assets/lib/matviz-embed.js">` +
  `<script>MatViz.mount("{prefix}", { theme:"auto" })</script>`. Unlike the
  3Dmol embeds it must **not** hardcode a background — theme follows `data-theme`.
- Inline data blocks (offline, no fetch): NaCl (CIF), Si (POSCAR), an XSF with
  vectors, and one small volumetric (XSF/CHGCAR) to show isosurface + `iso:`.
- **Deploy**: `matviz-embed.js` is copied into the host site's
  `assets/lib/matviz-embed.js` (and the recipes `static/lib/`) — documented,
  not automated here.
