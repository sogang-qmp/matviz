# v0.25 — 2D slice viewer + Brillouin zone plot + volume rendering

> **Roadmap provenance**: Tier 3 of the Crystal Viewer parity roadmap
> (v0.23–v0.26). See `Plan.md` §"Crystal Viewer parity roadmap".
> The heaviest tier — three substantial features. **May split into
> v0.25.x** if any one feature overruns (see "Phasing").

## Goal

Complete the manual's `Data` menu — MatViz today has only **Isosurface**
of the four display modes (Isosurface · Surface · Volumetric · Plane).
v0.25 adds the two highest-value remaining modes for physics analysis
(**2D slice / Plane** and **Volume rendering**) plus the **Brillouin
zone plot** that supports band-structure setup. "Surface mesh
(wireframe/shaded toggle)" is intentionally folded into the isosurface
material options rather than shipped as a separate mode (see D4).

## Scope (3 features)

| # | Feature | Success criterion |
|---|---------|-------------------|
| 25.1 | **2D Slice / Plane viewer** — sample the active grid on a plane (axis-aligned a/b/c index, or `(hkl)` Miller normal), map through a colormap + the v0.24 `ValueRange` (Level/Window/Mid-to-0), render into a panel canvas. Controls: plane selector, position (grid index or fractional), auto-range, colormap picker, PNG export. In-viewer the slice plane also shows as a textured quad in the 3D scene. | Loading a CHGCAR + selecting a slice shows a 2D contour that visibly tracks the 3D grid; changing index/plane updates live; auto-range and Mid-to-0 match the isosurface sign convention; PNG export works headless via CLI. |
| 25.2 | **Brillouin zone plot** — compute reciprocal lattice `b₁,b₂,b₃`; build the 1st BZ as the Wigner–Seitz cell of the reciprocal lattice; draw the polyhedron + reciprocal basis vectors + high-symmetry points/labels; optional k-path input (e.g. `GXWLGK`) drawn as a polyline. A "BZ ↔ Crystal" mode toggle; the axis-align buttons retarget to reciprocal directions in BZ mode. Special points seeded from the spglib lattice type (v0.20). | For a known lattice (fcc Si), the BZ polyhedron + Γ/X/W/L/K points render in correct positions; entering a path draws the polyline; toggling returns to the crystal view. |
| 25.3 | **Volume rendering** — WebGL2 3D-texture ray-marching of the active grid with an opacity/window transfer function driven by the v0.24 `ValueRange`; opacity + step-count controls; signed grids use the ±-color ramp. | A charge-density grid renders as a translucent volume where internal density variation is visible; adjusting window/opacity changes penetration; framerate stays interactive (≥30 fps) on a 128³ grid; degrades gracefully (or hides the mode) if 3D-texture size is exceeded. |

## Technical notes / decisions

- **D1 — Slice reuse.** The CLI renderer already has lattice-plane +
  `(hkl)` normal geometry (`--lattice-plane`, `viewNormalToPlane`
  `renderer.ts:1344`). 25.1 reuses that plane math for the sampling
  frame; the new work is grid sampling (trilinear) + colormapping + the
  2D panel. Sampling reuses the v0.23 grid arrays and v0.24 `ValueRange`.
- **D2 — BZ construction.** Wigner–Seitz of the reciprocal lattice =
  bounded intersection of half-spaces bisecting `G`-vectors to the 26
  nearest neighbors; take the convex polyhedron (reuse the
  `ConvexGeometry` path already used for coordination polyhedra
  `1d1ea8a`). Special-point tables are lattice-type-keyed (Setyawan–
  Curtarolo conventions); spglib (v0.20) supplies the Bravais type so we
  pick the right table. Ship the common lattices first (cubic P/F/I,
  tetragonal, hexagonal, orthorhombic); rarer ones degrade to "vectors +
  BZ only, no labels".
- **D3 — Volume rendering + CSP.** Ray-marching uses a WebGL2 3D texture
  + a fragment shader loop — **no `eval`, no new CSP relaxation** (unlike
  spglib WASM). Verify `dist/webview.js` size delta and that SwiftShader
  (CLI renderer) supports `texImage3D` — if not, volume mode is
  viewer-only and the CLI keeps isosurface/slice.
- **D4 — "Surface mesh" mode dropped as separate feature.** The manual's
  Surface (wireframe/shaded/shaded+wireframe of the grid) is low
  analytical value for our users; instead add a **wireframe/opacity
  toggle to the existing isosurface material** (small) so the capability
  exists without a fourth code path. Recorded as a deliberate scope
  narrowing.
- **D5 — Form factor.** The Crystal Viewer shows slice in a separate
  docked window (Layout 2). MatViz stays single-canvas: the 2D slice is
  a collapsible panel section with its own `<canvas>`, not a new OS/VS
  window. This matches the extension form factor and the v0.18 floating
  UI.

## Phasing (if needed)

If any feature overruns, ship in order of value:
`v0.25.0 = 25.1 (slice)` → `v0.25.1 = 25.3 (volume)` → `v0.25.2 = 25.2
(BZ)`. Slice has the highest day-to-day payoff (paper figures); BZ is
the most self-contained and can slip without blocking the others.

## Out of scope

- Transfer-function *curve editor* (arbitrary opacity vs value spline) —
  v0.25 ships preset ramps + window. Curve editing is future work.
- k-path → actual band-structure data overlay (that needs eigenvalues,
  a different data pipeline). v0.25 draws the path *geometry* only.
- Brick-based out-of-core volume rendering for grids exceeding
  `MAX_3D_TEXTURE_SIZE` — hide/deny the mode above the limit instead.

## Acceptance test fixtures

- CHGCAR / XSF signed grid — slice + volume with Mid-to-0.
- `silicon.poscar` (fcc) — BZ polyhedron + Γ/X/W/L/K + a `GXWLGK` path.
- A hexagonal fixture (graphene / a hex cell) — BZ special-point table
  coverage beyond cubic.
- 128³ grid — volume-render framerate check.

## Decision gate (kickoff)

**Gate v0.25-A** — confirm SwiftShader 3D-texture support for the CLI
before committing 25.3 to CLI parity. **Gate v0.25-B** — visual review
of slice + BZ on real fixtures before release (per the v0.18 Gate-C
pattern; floating/canvas chrome is theme-dependent).

## Exit criterion

Slice, BZ, and volume modes each work on their fixtures; volume adds no
CSP relaxation; the `Data` menu parity (Isosurface + Slice + Volume,
with BZ under Utilities) is complete; build + type-check clean;
SKILL.md/README updated. If phased, each v0.25.x ships independently.
