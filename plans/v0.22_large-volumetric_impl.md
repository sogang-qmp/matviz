## Reference findings (evidence base)

Captured 2026-05-19 during diagnosis. Do not relitigate — re-verify
only if surprised by behavior during implementation.

- **Node 20.20.2 limits** (`node -e "require('buffer').constants"`):
  - `MAX_STRING_LENGTH = 536_870_888` (≈ 512 MiB) — single JS string ceiling.
  - `MAX_LENGTH = 4_294_967_296` (4 GiB) — `ArrayBuffer` / `Buffer` ceiling.
- **`@types/vscode@1.85` `postMessage` JSDoc**
  (`node_modules/@types/vscode/index.d.ts:10000-10028`):
  - Signature: `postMessage(message: any): Thenable<boolean>` — **no
    transfer-list parameter**.
  - Since `engines.vscode >= 1.57`, embedded `ArrayBuffer` values
    inside `message` are "more efficiently transferred" and
    "correctly recreated inside of the webview". TypedArrays survive
    structured-clone with type preserved.
- **Our `engines.vscode`** = `^1.85.0` (`package.json:13`) — fast path
  is available, no engines bump needed.
- **Volumetric-producing parsers** (the entire surface for this work):
  - `src/parsers/cubeParser.ts`
  - `src/parsers/xsfParser.ts` (`parseDatagrid3D`)
  - `src/parsers/chgcarParser.ts`
- **Current 3× copy chain** for an N-point Float32 grid:
  - parser: `new Float32Array(N)` → 4N bytes (`cubeParser.ts:60`,
    `xsfParser.ts:321`, `chgcarParser.ts:61`).
  - host serialize: `Array.from(c.volumetric.data)`
    (`crystalEditorProvider.ts:165`) → 8N bytes boxed `number[]`.
  - structured clone → 8N bytes in webview process.
  - webview receive: `new Float32Array(data.data)`
    (`renderer.ts:983`) → 4N bytes.
  - **Total simultaneous RAM ≈ 24N bytes** (host 12N + webview 12N).

### New parser entry points

For each volumetric parser, add a sibling that consumes a
`Uint8Array` (or `Buffer`) instead of a `string`:

- `parseCubeFromBytes(bytes: Uint8Array): ...`  (new in `cubeParser.ts`)
- `parseXsfFromBytes(bytes: Uint8Array): ...`   (new in `xsfParser.ts`)
- `parseChgcarFromBytes(bytes: Uint8Array): ...` (new in `chgcarParser.ts`)

Each uses a **line iterator** that emits one decoded `string` at a
time without ever materializing the whole file as a string:

```ts
function* iterLines(buf: Uint8Array): IterableIterator<string> {
  let start = 0;
  const decoder = new TextDecoder('utf-8', { fatal: false });
  for (let i = 0; i < buf.length; i++) {
    const b = buf[i];
    if (b === 0x0A /* \n */) {
      // strip optional \r at end
      const end = (i > start && buf[i - 1] === 0x0D) ? i - 1 : i;
      yield decoder.decode(buf.subarray(start, end));
      start = i + 1;
    }
  }
  if (start < buf.length) {
    yield decoder.decode(buf.subarray(start));
  }
}
```

The numeric body of each parser then becomes:

```ts
const data = new Float32Array(totalPoints);
let idx = 0;
for (const line of iterLines(bytes)) {
  if (idx >= totalPoints) break;
  for (const t of line.trim().split(/\s+/)) {
    if (t === '') continue;
    data[idx++] = parseFloat(t);
    if (idx >= totalPoints) break;
  }
}
```

Each line as a string stays well under 512 MiB; only `bytes` (≤ 4 GiB)
sits in memory. Decoder is reused across iterations to avoid object
churn.

### Edge cases

- `\r\n` vs `\n` vs `\r` line endings — `iterLines` handles `\n`
  and `\r\n` natively; pure-`\r` Mac-classic files (rare) get
  treated as a single line which still parses correctly because
  `split(/\s+/)` doesn't care.
- BOM at start of file — `TextDecoder('utf-8')` strips it.
- Trailing partial line (no terminator) — handled by the
  `if (start < buf.length)` tail.

## Feature 22.3 — Load-time downsampling (Tier 3, opt-in)

### Configuration

Add to `package.json` `contributes.configuration.properties`:

```jsonc
"matviz.volumetric.maxGridPoints": {
  "type": ["number", "null"],
  "default": null,
  "description": "If set, downsample volumetric data on load when N_x*N_y*N_z exceeds this value. null = no cap."
}
```

### Downsampling strategy

Decimation (strided sampling), not averaging — preserves peak
amplitudes for isosurface visualization, cheap to compute, no
artifacts at typical stride 2–4.

```ts
function decimate(
  data: Float32Array,
  dims: [number, number, number],
  stride: number,
): { data: Float32Array; dims: [number, number, number] } {
  const [nx, ny, nz] = dims;
  const mx = Math.floor(nx / stride);
  const my = Math.floor(ny / stride);
  const mz = Math.floor(nz / stride);
  const out = new Float32Array(mx * my * mz);
  for (let i = 0; i < mx; i++)
    for (let j = 0; j < my; j++)
      for (let k = 0; k < mz; k++)
        out[i*my*mz + j*mz + k] =
          data[(i*stride)*ny*nz + (j*stride)*nz + (k*stride)];
  return { data: out, dims: [mx, my, mz] };
}
```

Choose smallest integer `stride` such that `(nx*ny*nz)/stride³
≤ maxGridPoints`.

### Where to apply

- **Tier 2 path:** integrate into `*FromBytes` parsers so we never
  allocate the full N-point Float32Array — choose `stride` first
  from header dims, then ingest only every `stride`-th value.
- **Tier 1 / standard path:** apply post-parse for simplicity.

### UI

Bottom-left info pill (already exists for symmetry) gains a
secondary line: `"isosurface: 300³ → 150³ (stride 2)"` when active.
