# v0.24 — Signed isosurface controls + value-range + centroid/COM

> **Roadmap provenance**: Tier 2 of the Crystal Viewer parity roadmap
> (v0.23–v0.26). See `Plan.md` §"Crystal Viewer parity roadmap".
> Depends on v0.23's named-grid model (signed grids need `kind:'signed'`
> and a selected grid to operate on).

## Goal

Turn the two **low-cost / high-payoff** gaps into shipped features. Most
of the rendering work already exists — v0.24 is mostly *exposing* and
*controlling* capabilities the renderer already has, plus one small new
measurement. The value-range state introduced here is deliberately
designed to be reused by v0.25's slice + volume rendering.

## Why this is cheap

- The renderer **already draws both + and − isosurface lobes**
  unconditionally (`renderer.ts:1125-1126`, `addLobe(+level, isoPos)` /
  `addLobe(−level, isoNeg)`) using two palette colors
  (`paletteColors().isoPos/.isoNeg`). There is simply no UI toggle. So
  "Show ± isosurfaces" is a control-surface addition, not new rendering.
- Measurement mode, atom selection, and the Measure HUD all exist
  (`main.ts:805`, `message.ts:33`). Centroid / center-of-mass is a new
  reducer over the existing selection set.

## Technical notes / decisions

- **D1 — Why value-range lives here, not v0.25.** The manual puts
  Level/Window + "Mid to 0" under the Charge-Density Viewer (used by
  Surface/Volumetric/Plane). Those display modes ship in v0.25, but the
  *value-range model* is small and also improves the existing
  isosurface (symmetric signed levels). Landing it now means v0.25's
  slice + volume consume a ready-made, already-tested `ValueRange`
  instead of inventing one. Per-grid `ValueRange` is stored alongside
  the grid selection from v0.23.4.
- **D2 — Default sign policy.** `kind:'signed'` grids (magnetization,
  σ components, DRHO, exciton phase) default to ±-on + Mid-to-0.
  `kind:'scalar'` grids (total charge, |ψ|²) default to single-sign,
  positive. This encodes the manual's guidance ("charge = single sign;
  magnetization = +/− Isosurface 권장") as a data-driven default.
- **D3 — Atomic masses.** COM needs standard atomic weights; add a
  `mass` column to `src/shared/elements-data.ts` (single source; keep
  the CLI subset in sync per CLAUDE.md). Absent-mass fallback → treat
  as centroid + warn once.
- **D4 — Marker rendering.** Reuse the measurement overlay group; the
  centroid marker is a small cross/octahedron billboard, disposed with
  the measurement group (no new lifecycle owner).
- **D5 — CLI parity.** `--iso-signed on|off`, `--iso-center <v>` /
  `--mid-to-0`, and centroid/COM are viewer-interactive; CLI parity for
  ± and center is worthwhile (`--iso-signed`, `--mid-to-0`); COM marker
  in headless is optional (defer if it complicates the still image).

## Out of scope

- 2D slice, BZ, volume rendering (v0.25) — this version only readies the
  `ValueRange` they depend on.
- Colormaps for volumetric data (v0.25) — 24.2's histogram uses a simple
  built-in ramp; full transfer-function editing is a v0.25 concern.
- Per-grid simultaneous overlay with independent opacity — still v0.25+.
