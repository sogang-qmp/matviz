# v0.23 — Multi-grid data model (CHGCAR spin + multi-DATAGRID)

> **Roadmap provenance**: Tier 1 of a 4-version parity roadmap
> (v0.23–v0.26) derived from a feature-gap analysis against the
> Genspark "Crystal Viewer" web workbench manual
> (`CrystalViewerManual.pdf`, 2026-07-22). See `Plan.md` §"Crystal
> Viewer parity roadmap" for the full tier map.

## Goal

Promote MatViz's volumetric data model from **one grid per structure**
to a **named list of grids per structure**, and use that to unlock the
two physics features MatViz silently drops today:

1. **CHGCAR spin decomposition** — `charge` / `magnetization`, derived
   `spin_up` / `spin_down`, and the SOC / non-collinear 4-block case
   (`magnetization_x/y/z`, i.e. the σ₁/σ₂/σ₃ components).
2. **Multiple `BEGIN_DATAGRID_3D` blocks** in one XSF (multiple exciton
   states, band-decomposed densities), each registered separately.

Both are *information-loss* bugs, not conveniences: today the parser
reads only the first grid block, so a user opening a spin-polarized
CHGCAR sees the total charge density and has **no way** to view the
magnetization, and an XSF exported from BerkeleyGW `plotxct` with N
exciton grids shows only grid #1.

## Why now / why first

The user's workflow is DFT / GW / **BSE** + magnetic materials. Both
missing features sit dead-center in that workflow. And architecturally
this must come first: every later tier (grid-selection UI in v0.24,
2D slice + volume rendering in v0.25) needs a way to address *which*
grid to display. Building those on the single-grid model would mean
building the multi-grid plumbing twice.

## Technical notes / decisions

- **D1 — CHGCAR block detection.** VASP interleaves `augmentation
  occupancies …` PAW blocks between grid blocks. The robust delimiter
  is the **repeat of the exact `nx ny nz` dimension line** that opened
  the first grid; everything between two such lines that isn't grid
  data (augmentation, per-atom lines) is skipped. Read `nx·ny·nz`
  floats after each dimension line. Guard: if a claimed grid block has
  fewer floats than `nx·ny·nz`, treat the file as malformed → fall back
  to single-grid (never crash).
- **D2 — Derived vs primary grids.** `spin_up`/`spin_down` are *derived*
  (computed, not stored). Tag them so the UI can group PRIMARY
  (`charge`, `magnetization`) vs DERIVED, matching the manual's Model
  Tree semantics — but keep it a flat list in v0.23 (tree UI is a v0.24+
  cosmetic layer).
- **D3 — Memory.** A 2-block collinear CHGCAR + 2 derived grids = 4×
  the grid RAM. For large grids this multiplies the v0.22 ceiling.
  Derive `spin_up/down` **lazily** on first selection, not at parse
  time; keep only `charge` + `magnetization` resident. Respect the
  existing `matviz.volumetric.maxGridPoints` stride during ingestion.
- **D4 — Message protocol.** Rename/extend `loadVolumetric` →
  `loadVolumetrics` (array). Keep a shim so a length-1 array reproduces
  today's path. Zero-copy `Float32Array` transfer (v0.20.1) preserved
  per grid.
- **D5 — Back-compat getter.** Everything downstream of the parser
  (isosurface, supercell tiling, CLI) reads `primaryVolumetric` until
  it's explicitly grid-aware. This keeps 23.1 a pure refactor with no
  behavior change, de-risking the later features.

## Out of scope

- Grid *rendering* beyond the existing isosurface (slice / volume →
  v0.25). v0.23 only makes multiple grids *addressable + isosurfaceable*.
- Simultaneous display of two grids with independent color/opacity
  (the manual's "동시에 켤 때 색상·opacity 조정"). Deferred to v0.24
  once the ± / color controls land.
- Model Tree hierarchical UI — v0.23 ships a flat grid list; tree comes
  with v0.24.
- Binary formats (`WAVECAR`, `.h5`) — unchanged from v0.22 out-of-scope.

## Decision gate (kickoff)

**Gate v0.23-A** — data-model shape review before writing parsers.
Pass criterion: `VolumetricGrid[]` + `primaryVolumetric` getter compiles
and the 23.1 pure-refactor render is byte-identical on all existing
volumetric fixtures. On fail: reconsider whether to carry a single-grid
fast path.

## Exit criterion

A spin-polarized CHGCAR and a multi-DATAGRID XSF each expose all their
grids in the side-panel list and via `--grid`; every existing volumetric
fixture is unchanged; `tsc --noEmit` + `npm run build` clean; SKILL.md +
README updated for `--grid`.
