# v0.23.4 — Grid selection UI + `--grid` CLI + persistence — completion log

**Status**: ✅ complete. **Date**: 2026-07-22. Closes v0.23 feature work.

## What shipped

Made the parsed named-grids user-selectable (webview + CLI), the last piece
on top of 23.1's `getGridNames()`/`setActiveGrid()` and 23.2/23.3's parsers.

### Webview
- `crystalEditorProvider.ts` — new `#grid-section` panel section (a
  `<select id="grid-select" class="panel-select">`) placed above `#iso-section`.
- `main.ts` — `applyVolumetricUi` split into:
  - `populateGridSelect()` — fills the select from `renderer.getGridNames()`
    via DOM API (injection-safe), shows the section only when >1 grid,
    restores the persisted active grid, and binds a `change` handler that
    calls `renderer.setActiveGrid()` → `syncIsoPanel()` → `debouncedSave()`.
  - `syncIsoPanel()` — extracted iso slider/input wiring, re-run on grid switch
    so the iso range/level track the newly active grid.
- Persistence: `PersistedState.activeGrid` (saved via
  `renderer.getActiveGridIndex()`, restored in `populateGridSelect`).

### CLI (`scripts/render.ts`)
- `--grid <name>` selects the named grid before isosurfacing; unknown names
  print the available list to stderr and fall back to the first grid.
- Help text + SKILL.md (flags table + spin-CHGCAR recipe) + README updated.

## Bug found & fixed (end-to-end)
`parseStructureFileTrajRaw`'s single-frame fallback forwarded only
`volumetric` (= grid[0]), **dropping `volumetrics`**. Since CHGCAR is not a
trajectory format it takes this fallback, so the whole named-grid list
collapsed to a single grid before reaching the CLI/webview. The CLI `--grid`
test (charge vs magnetization rendering identical) surfaced it; unit-level
leaf-parser tests could not. Fixed by forwarding `volumetrics` too.

**Lesson**: multi-grid must be verified through `parseStructureFileTraj` (the
real entry point), not only the leaf parsers.
