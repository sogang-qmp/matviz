**Date**: 2026-07-22
**Status**: complete, verified.

## What shipped

`src/webview/embed/ui.ts` — `createEmbedUI(host, renderer, opts)`, a lean
collapsed-first control overlay built fresh on top of `CrystalRenderer` (does
NOT port the VSCode webview chrome — architecture decision from the 21.1
check-in, confirmed by the user "계속 진행" = proceed with the recommended path).

### DOM (all inside `#{prefix}-viewer`, namespaced by `.mv-*`)

- **`.mv-info`** (bottom-left, low chrome): `formula · spaceGroup · N atoms · V Å³`
  from `renderer.getStructureInfo()`. `opacity:.6`, `pointer-events:none` — a
  figure caption, not a control.
- **`.mv-toggle`** (top-right): `⋯` affordance, `opacity:.5` → `1` on hover.
- **`.mv-panel`** (top-right, hidden until open): Style chips (4 display styles,
  active = accent), Supercell `− n +` steppers (a/b/c, clamp 1–8), Isolevel
  slider (volumetric only, from `getIsoRange()`), Reset view + Bonds buttons.

### Collapse/expand

- Default collapsed (`opts.collapsed !== false`).
- `⋯` toggles `data-open` on the host; **Esc** and **click-away**
  (`pointerdown` outside the panel) collapse. `collapsed:false` starts open.

### Styling

One `<style id="matviz-embed-css">` injected once per page (inline styles are
allowed by the recipes/site sandbox CSP — unlike the nonce-only VSCode webview).
Colors reference host CSS vars (`--fg`/`--border`/`--accent`/`--bg`) with
fallbacks; aux text via `opacity` (house rule) → the chrome adapts to the host
light/dark theme with no extra code.

## Axis-indicator drag (added 2026-07-22, user request)

The VSCode webview lets you drag the a/b/c gizmo to reposition it (right-click,
`main.ts:741-777`). The lean embed dropped that with the rest of `main.ts`'s
canvas wiring, so a user couldn't move it. Added `attachAxisDrag(canvas,
renderer)` in `embed/index.ts`: **right-click** drag on the gizmo (user chose
right-click for VSCode parity) via a **capture-phase** `pointerdown` that
hit-tests `renderer.getAxisIndicatorRect()` and `stopImmediatePropagation()` so
neither the renderer's left-drag rotation nor OrbitControls' right-drag pan
fires; misses fall through to normal pan. The canvas `contextmenu` is suppressed
so the browser menu doesn't interrupt the drag. Offset math
(`setAxisIndicatorOffset(baseX-newX, baseY-newY)`, bottom-right anchor) mirrors
`main.ts`. Hover shows a `move` cursor. Cleaned up in `dispose()`.

Iterated left-click → right-click per user request (2026-07-22).

Verified (puppeteer): hover over gizmo → `cursor:move`; **right-drag** relocates
the gizmo (bottom-right → top-center) **without rotating the structure**; a
left-drag still rotates; VSCode bundle still byte-identical; build/tsc clean.
