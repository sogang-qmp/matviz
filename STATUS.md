# Project Status

- **Version**: v0.22.0 (large-volumetric data support) shipped 2026-05-19. Three-tier work that takes MatViz from "dies with `RangeError: Invalid string length` on volumetric files > 512 MiB" to "opens any ASCII cube/XSF/CHGCAR up to 4 GiB on disk, with automatic load-time decimation when the grid would otherwise exceed the 4 GiB ArrayBuffer ceiling." Tier 1 shipped earlier as v0.20.1 (volumetric zero-copy postMessage hotfix, 2026-05-19) on top of v0.20.0 (combined editor integration + spglib symmetry detection, 2026-04-27). Bundles the entire v0.19 (editor integration) and v0.20 (symmetry) feature sets per the user's reorder + combined-release decision. **v0.19** features (editor): full migration from `CustomReadonlyEditorProvider<CrystalDocument>` to `CustomTextEditorProvider` for live text-buffer editing with 250 ms debounced reparse (19.1); `matviz.defaults.*` settings namespace exposing 7 user-configurable defaults — style, palette, showBonds, showBoundary, cameraMode, bondCutoffPad, axisIndicatorSize (19.2); session-scoped property-panel undo/redo via `Ctrl+Z` / `Ctrl+Shift+Z` capped at 50 entries, covering element color/radius/visibility + per-pair bond min/max/enable (19.3). **v0.20** features (symmetry): `@spglib/moyo-wasm@^0.7.9` integration with 700 KB raw size guard (20.1); `withSymmetry()` post-parser pass on every `parseStructureFile`/`parseStructureFileTraj` with CIF-deference, frame-0-only trajectory policy, Cartesian↔fractional transpose fix (20.2); info-pill correct space group on every non-CIF format (20.3); CLI `--info` text + `--info --json` modes that exit sub-100ms without launching Puppeteer (20.4); host-side architecture caveat docs — webview never loads WASM, no CSP relaxation needed (20.5). Cross-validation against 6 fixtures (silicon Fd-3m, NaCl Fm-3m, BCC Fe Im-3m, BCC Cr Im-3m, MAPbBr3 Pm, graphene P6/mmm) all passed. Third-party license attribution (`THIRD_PARTY_LICENSES.md`) added for `three.js` + `@spglib/moyo-wasm`. v0.19.0 tag intentionally skipped — single sequence-monotone v0.20.0 tag. Earlier v0.18.1 shipped 2026-04-27 (light theme + vector overlay generalization + QE ibrav).

- **v0.22.0** (2026-05-19): Large-volumetric data support — closes the V8 string-heap ceiling (~512 MiB) that made ASCII XSF / cube / CHGCAR files at exciton-wavefunction scale uncopable. **Feat 22.1** shipped earlier as v0.20.1 (postMessage zero-copy). **Feat 22.2** (raw-byte parser path): new `src/parsers/lineIterator.ts` (`iterLines`, `findBytes`, `offsetAfterLines`); `parseCubeFromBytes` / `parseXsfFromBytes` / `parseChgcarFromBytes` reuse existing header parsers and only run line-by-line over the data-grid byte slice; `crystalEditorProvider.parseDocumentInitial` stat-gates at 256 MiB and routes large files through `vscode.workspace.fs.readFile` → `parseStructureFileTrajFromBytes`, bypassing `TextDocument.getText()` entirely; reparse-on-edit disabled for raw-byte loads. Bit-equal Float32 grids verified vs string path on `h2o.cube` and `LiF-polaron-isolevel.xsf`; 297 MiB synthesized cube confirms the 256 MiB gate fires and adds ~zero RSS overhead beyond the Float32Array itself. **Feat 22.3** (load-time downsampling): new `VolumetricLoadOptions.maxGridPoints` + `chooseStride()` helper + `VOLUMETRIC_SAFETY_MAX_GRID_POINTS = 4×10⁸` default (well below 4 GiB ArrayBuffer ceiling); stride applied **during ingestion** so the full-resolution Float32Array is never allocated for oversized grids; isotropic (single integer stride across all three axes); new VSCode setting `matviz.volumetric.maxGridPoints` (null = safety default). **Info pill** shows e.g. `iso: 1024³ → 512³ (stride 2)` when decimation was applied, both equal-axes (cube form) and asymmetric (`A×B×C`) handled. End-to-end: any ASCII volumetric file ≤ 4 GiB on disk now loads.

- **Polyhedra off on file init** (locked 2026-04-21): `showPolyhedra` not restored from saved state.
- **Polyhedra auto-detect heuristic** (locked 2026-04-21): first-coordination-shell heteroatomic + aggregated dominant ligand ≥ 85%.
- **Isosurface supercell = PBC tile + single MC + outer caps** (locked 2026-04-22): option 2 from the day's discussion.
- **CrystalTrajectory wrapper + dual parser API** (locked 2026-04-23 v0.17.1.0): `parseStructureFile` (single-frame, all existing call sites) + `parseStructureFileTraj` (trajectory-aware, new entry). Length-1 trajectory wraps single-frame for uniform downstream code.
- **Bond recompute default off in trajectory playback** (locked 2026-04-23 v0.17.1.5): inherit frame-0 bonds across frames; toggle for opt-in per-frame recomputation; auto-disable above 5k atoms.
- **PBC-aware NN matching when same lattice REF** (locked 2026-04-23 v0.17.2.2): minimum-image distance via fractional round; raw cartesian when cells differ.
- **Bundled v0.16+v0.17+v0.17.1+v0.17.2+v0.17.3 release** (locked 2026-04-23): single jump 0.15.2 → 0.17.3 with one tag (option A).
